# 新潟ペアリングラボ / Niigata Pairing Lab

新潟の酒と食を起点に、地域資源の「飲む理由」「選ぶ理由」「売れる場面」を調査・実証し、一次情報として蓄積するプロジェクトです。

> 現在は構想・設計段階です。名称、ロゴ、掲載情報は、権利・出典・協力者の許諾を確認してから公開します。

## 目指すもの

新潟清酒を最初の入口として、酒蔵・飲食店・売場・生活者をつなぎ、ペアリング、飲み方、売場づくり、共同企画を小さく試します。情報量を競うメディアではなく、現場で検証した学びと、その根拠を残す「需要開発ラボ」を目指します。

## 事業の4フェーズ

| Phase | 役割 | 取り組み |
|---|---|---|
| 1 | 信頼形成・現場参加 | 新潟県内の情報発信、コミュニティ参加、取材、軽いコンサルティング |
| 2 | 県内需要開発 | 販路・売場改善、ペアリング、飲み方、日本酒カクテルの提案と実証 |
| 3 | 地域間共創 | 新潟清酒と他都道府県の名産を組み合わせた共同企画 |
| 4 | ハブ運営 | 日本酒以外も含む新潟の地域資源と各地の名産をつなぐ情報・共創基盤 |

今回構築するのは **Phase 1のMVPのみ** です。後続フェーズのEC、受発注、販売仲介、マーケットプレイスは先回りして実装しません。

## Phase 1で検証すること

- 事実、当事者発言、運営者の観察、仮説を区別して公開できるか
- 出典、確認日、許諾、訂正履歴を無理なく管理できるか
- 酒蔵・飲食店・売場との共同実験につながるか
- ペアリング案を、条件・反応・限界・次の検証まで記録できるか
- 掲載数ではなく、再注文・継続採用・紹介などの行動変化を捉えられるか

## 設計原則

- 一次情報と現場実証を優先する
- 根拠のない「公式」「認定」「網羅」表現を使わない
- AI生成内容を事実として公開しない
- 写真、ロゴ、インタビューは許諾確認後に掲載する
- 個人情報、商談メモ、連絡先、契約、見積、未公開情報をリポジトリへ置かない
- D3による可視化は、少数データではなく意思決定価値が生まれた場合だけ採用する
- 酒類の売買契約・受発注・媒介は免許を持つ事業者が担う
